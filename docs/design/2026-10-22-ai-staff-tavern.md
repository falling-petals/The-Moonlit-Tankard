# 月光酒馆：AI店员玩法设计稿

更新：2026-10-22。本文记录已确认方向和建议默认值，尚未实现游戏。

## 已确认的方向

- 桌面浏览器运行的2D像素风酒馆经营游戏。
- 第一版个人自用；纯前端，无自建后端，强调打开即可开始经营。
- 同一酒馆昼夜切换：白天使用C的温馨温室空间，夜晚参考B的青蓝雨光与珊瑚灯光；建筑、家具与布局保持一致。
- AI NPC均为可雇佣店员，不是顾客。厂商对应形象由用户后续提供；不同AI有不同性格。
- 顾客是一系列像素小人，按游戏规则产生点单和服务请求，不为每个顾客调用大模型。
- AI互动真实调用大模型。
- 岗位安排后自动工作，玩家可以临时指派任务。
- 性格影响表达、偏好和少量工作行为；工作能力可以通过技能培养成长。
- 互动包括与玩家交谈、店员间交谈、响应顾客请求，以及之前提出的偏好理解、持续记忆、关系发展、由互动触发的小任务与事件。

## 将原先的顾客互动改为店员互动

| 互动 | 店员身份下的表现 | 游戏中的结果 |
| --- | --- | --- |
| 理解需求 | 从顾客的口味或服务请求中理解需求，必要时追问 | 提出饮品建议，或执行可用服务动作 |
| 记忆 | 记住玩家的安排、常见工作情境、同事合作经历和顾客的可记录偏好 | 后续对话与工作建议能引用真实经历 |
| 店员关系 | 交接、协作、闲聊、产生意见分歧和相互熟悉 | 解锁合作对话及共同事件；具体数值效果待定 |
| 主动建议 | 根据库存、天气、客流或共同经历提议 | 建议调整菜单、举办活动或改善布置 |
| 小任务与事件 | 提出试调饮品、团队聚会、主题夜等请求 | 玩家选择是否推进；完成后留下配方、装饰或纪念物 |
| 对玩家回应 | 玩家询问工作、了解想法或作出临时安排 | 店员结合当前岗位、性格及记忆回应 |

人物性格与故事均为游戏创作，不代表厂商真实产品能力。店员形象与实际调用的模型服务分别配置；是否为不同角色绑定不同模型尚未确定。

## 建议的营业循环

开店前采购、备料和排班；营业中接单、制作、送餐、收桌并处理请求；空闲时与店员交谈、调整布置；夜间可举办活动；打烊后结算、查看留言和安排明天。

保留常见经营内容：菜单与配方、库存采购、酿造熟成、员工培训、空间与动线、设备升级、昼夜经营、活动与声望。首版具体数量与深度仍待确定。

## 建议的AI与经营协作规则

- 寻路、排队、工作进度、库存、价格和结算由游戏规则即时处理。
- 服务行为与语言回应分别调度；模型等待期间继续正常营业。
- 顾客请求具有明确的游戏事件和可选动作，AI结合事件组织回应与提出选择。
- 玩家交谈和紧急服务请求优先，同事闲聊按事件触发并限制频率。
- AI提出的任务和经营建议，需要落在当前已实现的规则范围内；重要经营安排由玩家决定。
- 模型不可用时继续经营，并保留基础服务提示；真实AI功能在连接恢复后继续。

## 个人自用下的纯前端接入建议

- 在设置中配置模型服务地址、模型名称和个人API凭据。
- 游戏静态资源中不包含个人API凭据。
- 先进入经营场景，使用AI功能时完成连接配置；配置成功后可测试对话。
- 经营档案在浏览器本地自动保存，提供导入和导出。
- 个人凭据的记住方式单独设置，不随普通游戏存档导出。
- 接口供应商确定后，实际验证其浏览器直接访问、鉴权方式和错误处理。

## 后续需要明确

1. 模型供应商与接口形式，以及所有店员共用一个模型还是分别绑定。
2. 用户提供各AI形象和希望保留的性格特点。
3. 首版店员数量、岗位划分、饮品数量和经营压力。
4. 昼夜时长及对话时是否暂停：建议默认正常经营，可手动暂停。

以上未定事项不影响本轮玩法方向整理；进入对应实现前再确定。
